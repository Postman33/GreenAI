# Очистка инженерных сетей

Этот экспериментальный модуль отделяет вероятные оси инженерных сетей от
букв, стрелок, выносок и других CAD-примитивов, которые лежат на тех же слоях.
Он пока не подключён к расчёту допустимых зон посадки: результат сначала нужно
проверить в nanoCAD.

## Алгоритм

Для каждого типа сети выполняются четыре шага:

1. Отбрасываются микролинии и небольшие замкнутые контуры.
2. Из достаточно длинных и почти прямых примитивов строятся связные компоненты
   с небольшим допуском на разрывы. Связь учитывается через концы линий:
   случайное пересечение буквы с трубой посередине не объединяет их.
3. Компонент принимается за трассу, только если у него достаточны общая длина
   и пространственный размах.
4. К принятому скелету возвращаются короткие соединители, у которых оба конца
   касаются скелета. Одиночные штрихи и боковые элементы букв не возвращаются.
5. После сборки удаляются короткие симметричные пары линий, образующие острый
   `V`, а также выноски из более длинного хвоста и короткого наклонного уса.
   Они записываются с причиной `arrow_or_leader` и остаются видны на красных
   отладочных слоях.
6. Одиночная длинная линия не считается доказанной трассой: это может быть
   выноска к подписи. В `CLEAN` она попадает только при наличии почти
   коллинеарного продолжения через общий конец; иначе переносится в `REVIEW`.

Это эвристика. Выход всегда имеет статус `heuristic_requires_visual_review`.
Результат делится на подтверждённую трассу, сомнительные боковые ветви для
ручной проверки и отклонённую графику.
Только зелёный класс `CLEAN_*` рассматривается как кандидат для будущего
автоматического буфера; даже его необходимо один раз подтвердить в CAD.
Особенно сложные слои можно отключить в `config.yaml`. ЛЭП отключена, потому
что в текущем файле она состоит из несвязанных штрихов примерно по 2,5 м.

## Запуск на текущем примере

```powershell
.\.venv\Scripts\python.exe .\utility_cleaner\clean_utilities.py `
  .\output\extracted_objects.jsonl `
  --work-boundary .\output\normalized_objects.geojsonl `
  --output .\output\cleaned_utilities.geojsonl `
  --review-output .\output\review_utility_graphics.geojsonl `
  --rejected-output .\output\rejected_utility_graphics.geojsonl `
  --report .\output\utility_cleaning_report.json `
  --debug-dxf .\output\utility_cleaning_debug.dxf `
  --debug-png .\output\utility_cleaning_debug.png
```

В отладочном DXF:

- `CLEAN_WATER_PIPE`, `CLEAN_SEWER_PIPE` и аналогичные слои — принятые линии;
- `REVIEW_WATER_PIPE`, `REVIEW_SEWER_PIPE` и аналогичные — неоднозначные
  боковые ветви, которые нельзя автоматически считать трубой или стрелкой;
- `REJECT_WATER_PIPE`, `REJECT_SEWER_PIPE` и аналогичные — отсеянная графика;
- `CLEAN_WORK_SCOPE` — граница области анализа с внешним запасом 20 м.

Числовые пороги хранятся в `config.yaml`, а в отчёте фиксируются фактически
применённые значения и доля сохранённой длины для каждой сети.
