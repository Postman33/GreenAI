# Sylvitect-core: план демонстрации на Windows

Сценарий для выступающего: Windows, PowerShell, nanoCAD и PDF-просмотрщик. Объект — **3-я Парковая**. Основная история: исходный DXF → распознавание сетей → ограничения → план посадок → объяснение конкретного решения → новый DXF с сохранённой подосновой.

Ориентир — **9 минут 40 секунд**, допустимый интервал по ТЗ — 4–10 минут. Последний полный расчёт занял 7 минут 44 секунды при работающей БД. Открытие CAD и генерация фотографий в это время не входят. Перед защитой нужен один прогон с секундомером, включая открытие нового DXF.

## Короткая шпаргалка

1. Показать исходный чертёж и сразу запустить полный расчёт.
2. На журнале показать извлечение слоёв, ONNX и восстановление сетей.
3. Пока идёт расчёт, объяснить ограничения на подготовленном участке У-17.
4. Показать, как читается паспорт принятой посадки `T-0001`.
5. После завершения открыть **DXF текущего запуска**, переключить слои результата.
6. Найти эту посадку в свежем PDF, показать расстояние, порог и нормативную ссылку.
7. Показать `verification_report.json`: ошибки отсутствуют, исходные сущности сохранены.
8. Если остаётся время, показать подготовленную пару изображений «до/после».

Главная фраза выступления:

> «Мы получаем из DXF план озеленения, в котором можно проверить место каждой посадки: увидеть применённые ограничения, измеренные расстояния и основание решения».

## Подготовка запуска

До начала отсчёта открой Docker Desktop, дождись его готовности и запусти БД:

```powershell
Set-Location 'F:\Пилотный проект 20 улиц'
docker compose up -d --wait postgis

$demoSource = (Resolve-Path -LiteralPath '.\Пилотный проект 20 улиц\input_10001759_bound.dxf').Path
$demoInputHash = (Get-FileHash -LiteralPath $demoSource -Algorithm SHA256).Hash
```

Каталог растений и правила должны быть уже подготовлены. Переустановка зависимостей, обучение моделей и повторное заполнение БД в живую демонстрацию не входят.

### Изображения подготовить перед выступлением

Обычный запуск меню уже включает Blender и OpenRouter. Дождись предварительной генерации и выбери удачную пару из:

```text
output\latest\blender_gallery\place_01\photorealistic\
```

Файлы обзорного ракурса начинаются с `overview_before__` и `overview_after__`; пешеходного — с `pedestrian_before__` и `pedestrian_after__`. Следом идёт короткий отпечаток содержимого, чтобы повторный запуск сохранял оплаченные изображения. Расширение зависит от ответа API. Если готова только одна полная пара, её достаточно для показа бонуса. Blender-оригиналы лежат рядом в папке `renders`.

Сохрани готовые изображения отдельно от папки нового прогона, чтобы легко открыть их на защите. Укажи, что они подготовлены заранее по тому же варианту посадок. Состав и координаты в визуализации должны относиться к показываемому плану.

### Живой запуск

```powershell
.\scripts\run_pipeline_interactive.ps1
```

В меню уже выбраны 3-я Парковая, **«Полный DXF»** и **«Плотная смешанная»**. Для показа с лимитом 10 минут рекомендую выключить повторную генерацию фотографий: **5 → 2 → 0**. Затем **6 — «Построить план»**. Настройка действует в этом открытом меню; при следующем запуске фотореализм снова включён по умолчанию.

Показать на экране перед стартом:

```text
InputDxf = ...\input_10001759_bound.dxf
PipelineMode = full
PlantingPreset = dense_mixed
```

Запомни `OutputDirectory`. Для этого сценария требуется полный прогон: он создаёт новый DXF с подосновой. В режиме `fast` результатом служит отдельный оверлей.

## Что переключать в nanoCAD

В менеджере слоёв найди имена по таблице. В финальном DXF сначала показывай только три слоя посадок вместе с подосновой. Зоны включай по одной, чтобы результат оставался читаемым.

| Слой | Что показываешь и объясняешь |
|---|---|
| `SYLVITECT_PLANT_TREE` | Предложенные деревья; на У-17 два зелёных круга. Круг показывает условный габарит посадки. |
| `SYLVITECT_PLANT_SHRUB` | Предложенные точки кустарников. В этом демо это дерен белый. |
| `SYLVITECT_HERBACEOUS` | Площади травянистого покрытия. |
| `SYLVITECT_ZONE_TREE` | Территория после применённых отступов для деревьев; по умолчанию выключена. |
| `SYLVITECT_ZONE_SHRUB` | Территория после применённых отступов для кустарников; по умолчанию выключена. |
| `SYLVITECT_RECONSTRUCTED_ROAD` | Восстановленная дорога; по умолчанию выключена. |

Для связки «объект → паспорт» выбери круг дерева, покажи координаты его центра в свойствах и сопоставь их с PDF. ID записан также в XDATA `SYLVITECT`; для демонстрации достаточно центра и паспорта.

Если попросили подробно показать коммуникации, используй заранее открытый [диагностический DXF](../output/submission_verification_20260929/planting_diagnostics.dxf):

- `DEBUG_CLEAN_HEAT_PIPE` — принятая геометрия теплосети.
- `DEBUG_EXCL_TREE_HEAT_2` — исключающая зона теплосети для дерева.
- `DEBUG_ALLOW_TREE` — допустимая область деревьев после правил.
- `DEBUG_REJECTED_TREE` и `DEBUG_REJECTED_TREE_IDS` — отклонённые кандидаты и их ID.
- `DEBUG_REJECT_REASONS` — выноски причин, включаются при необходимости.

Открывать диагностический файл в основной части необязательно: он большой. Полный DXF, один паспорт и проверка результата важнее для лимита времени.

## Проверка свежего результата

Дождись сообщения **`Pipeline completed`** и сверь имя папки в строке `Final DXF`. Наличие файла во время записи ещё не означает готовность результата. Если фотореализм оставлен включённым, после этой строки продолжатся Blender и OpenRouter; готовые расчётные файлы уже можно показывать.

Открой в текущей выходной папке:

1. `result_with_planting_plan.dxf` — новый полный чертёж в nanoCAD.
2. `sylvitect_planting_report.pdf` — паспорт выбранной посадки.
3. `verification_report.json` — итог независимой проверки.

Для короткого вывода проверки в том же PowerShell после завершения скрипта:

```powershell
# Если меню выбрало output\run_..., укажи здесь напечатанную папку.
$demoResult = Join-Path (Get-Location).Path 'output\latest'
$demoCheck = Get-Content -LiteralPath (Join-Path $demoResult 'verification_report.json') -Raw -Encoding UTF8 | ConvertFrom-Json
$demoCheck | Select-Object status, failures
$demoCheck.dxf_checks | Select-Object input_modelspace_entity_count, preserved_source_entity_count, missing_source_entity_count, changed_source_content_count
$demoCheck.planting_plan_checks | Select-Object measured_distance_failure_count, missing_explanation_count, missing_npa_reference_count

# Сравнивается с контрольной суммой, вычисленной до запуска.
(Get-FileHash -LiteralPath $demoSource -Algorithm SHA256).Hash -eq $demoInputHash
```

Ожидаемый ориентир при тех же данных и настройках: `passed`, `failures: []`, сохранено **4 743 из 4 743** исходных сущностей модели; остальные показанные счётчики — 0. Последняя команда возвращает `True`, если сам входной файл не изменился. После проверки чисел покажи читаемый DXF в CAD: это отдельная часть демонстрации.

Контрольный план всей улицы: **38 деревьев, 4 030 кустарников, 135 участков травянистого покрытия**. По изменённым настройкам числа могут отличаться; озвучивай свежий отчёт.

## Если время заканчивается

Сначала убери пешеходный ракурс, пример отказа и подробную диагностику. Сохрани четыре действия: новый DXF, слои результата, принятая посадка с нормативной ссылкой, итог проверки.

Если CAD долго открывает новый файл, покажи свежий PDF и отчёт, пока он загружается. Если расчёт или открытие не завершились к лимиту, переход к подготовленному результату нужно прямо назвать резервным показом; он не подтверждает успешность текущего запуска. Если полная репетиция превышает 10 минут, сценарий ещё не готов к этому лимиту.

Эта демонстрация подтверждает работу в **Windows/nanoCAD**. Указанное в ТЗ открытие результата на МосТех.ОС/Linux требует отдельной проверки на целевой системе.
