# Проверка запуска Windows и Linux

Дата: 29 сентября 2026 года. Проверялся проект из распакованного `Sylvitect-core.zip`, контрольный DXF — 3-я Парковая, пресет `dense_mixed`, режим `full`.

| Проверка | Windows | Linux |
|---|---|---|
| Среда | Windows x64, сборка 26200; Python 3.10.11 | Debian Bookworm, Python 3.11.16, Docker Desktop / WSL2, x86-64 |
| Установка | `init.ps1 -SkipDocker -NoSystemInstall`: новое `.venv`, зависимости из `poetry.lock` | `install.sh --skip-docker`: новое `.venv-linux`, зависимости из `requirements.txt`, загрузка и сборка Go 1.25.5 |
| Загрузка демо | Реальное скачивание через `init.ps1`, размер и SHA-256 подтверждены | Реальное скачивание через `init.sh --skip-install`, размер и SHA-256 подтверждены |
| Первый запуск | `run.ps1`, полный расчёт из распакованной папки | Сборка Dockerfile из распакованного проекта и полный расчёт в контейнере |
| База | Доступный PostGIS найден автоматически | Отдельный новый PostGIS, инициализация через `init.sql` |
| Меню и пути | Проверки PowerShell, пути с кириллицей и пробелами | Реальный Bash, `run.sh --validate-only` и интерактивное меню `--dry-run` |
| Python-тесты | 250, OK | 250, OK; пропущены 4 проверки Windows PowerShell |
| Go-тесты | Все три пакета прошли | Все три пакета прошли |
| Полный пайплайн | `passed`, 541,9 с | `passed`, 737,7 с |
| Выходные файлы | Полный DXF, диагностика, PDF-отчёт, PDF-атлас, объяснения и проверка | Тот же набор |

Время измерено при параллельных проверках на одной машине. Linux записывал файлы через подключённую папку Windows; эти числа не являются сравнением производительности ОС.

## Сверка результатов

- 38 деревьев, 4 030 кустарников, 135 участков травянистого покрытия на обеих платформах.
- Все 4 203 ID и статуса совпали. Геометрии совпали с допуском 10⁻⁷ единицы DXF.
- `verification_report.json`: `passed`; исходные 4 743 сущности модели сохранены, отсутствующих объяснений нет.
- Отчёты PDF созданы на обеих платформах. Шрифты и переносы строк могут различаться.

Локальные артефакты проверки находятся в `output/platform_linux_check` и `tmp/project_delivery_check/Sylvitect-core/output/windows_full_check`. В архив проекта они не включаются; при запуске пользователь получает собственный результат.

## Исправления по результатам проверки

1. Windows-установщик больше не использует случайно активированное Python-окружение другого проекта. Poetry создаёт `.venv` внутри распакованной папки.
2. В архив добавлен `inspect_dxf.py`, необходимый для диагностики и тестов.
3. Windows-скрипт тестов учитывает код завершения Python/Go; обычный вывод в stderr при перенаправлении в лог не обрывает тестирование.
4. Проверка содержимого PDF допускает переносы строк между словами, зависящие от шрифта ОС.

## Что требует отдельной проверки

Полный расчёт подтверждён на Windows и в Linux-контейнере Debian. Нативная установка Docker на новой машине, другие дистрибутивы и конкретная сборка МосТех.ОС отдельно не испытывались. Для установки Windows Python, Go и Docker уже были доступны; автоматическая установка этих системных программ через winget не проверялась.

Открытие DXF в графическом CAD и оценка восстановленной дороги остаются ручной проверкой. Blender и платная генерация OpenRouter в этот прогон не входили.
