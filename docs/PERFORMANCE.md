# Оптимизация расчёта посадок

Изменения от 27.09.2026. Настройки посадок, ограничения, состав выходных файлов и команды запуска сохранены. Оптимизации используются автоматически при обычном запуске пайплайна.

## Что изменено

| Участок | Изменение | Что сохраняется |
|---|---|---|
| Проверка соседних посадок в планировщике | Индекс принятых точек по запросам/профилям. Основная часть точек хранится в STRtree; новые точки немедленно доступны через небольшой буфер до перестроения индекса | Точное расстояние, ближайший сосед, наиболее сильное нарушение шага; при равенстве — исходный порядок принятия точек |
| Перебор схем размещения | Индекс уже занятых точек строится один раз для компонента и используется во всех вариантах поворота и сдвига | Все варианты, порядок их сравнения, выбор победителя и журнал отсеянных точек |
| Проверка сетки внутри полигона | Координаты передаются в GEOS пакетами по 256 точек | Исходная арифметика координат, порядок генерации, отверстия и включение точек на границе |
| Диагностические продолжения рядов | Соседние принятые точки находятся через STRtree | Диапазон расстояний, порядок при равенстве и набор диагностических кандидатов |
| Независимая проверка шага | Пространственный индекс отбирает потенциально конфликтующие пары; для них вычисляется точное расстояние | Оба габарита, индивидуальные шаги, масштаб DXF, совпадающие точки и исходный допуск сравнения |
| Проверка сохранности DXF | Числовые координаты компилируются только в разделах, используемых манифестом: ENTITIES и TABLES | Прежний состав сравниваемых записей, отпечатки содержимого, ID посадок и состояния слоёв |
| Исключающие зоны в диагностике | Перед построением буфера отбираются целые части инженерных линий, способные затронуть базовую область | Радиус отступа и форма исходных линий; контуры зданий обрабатываются прежним способом |

Отбор соседей учитывает максимальный возможный порог для пары. Поэтому крупное растение с большим отступом не теряется, даже если оно находится дальше обычного шага текущего растения. Генератор и независимый верификатор используют отдельные реализации проверок.

В диагностике линии не обрезаются перед построением буфера: такое обрезание создало бы искусственные концы. Проверка исходного DXF и аудит экспортируемой копии остаются включёнными.

## Проверка эквивалентности

Для 3-й Парковой использованы одинаковые промежуточные данные контрольного прогона и пресет `dense_mixed`. Сравниваются:

- `planting_plan.geojsonl` — координаты, типы, виды растений, результаты нормативных проверок;
- `planting_decisions.geojsonl` — принятые и отклонённые точки с объяснениями;
- `planting_layout_trace.jsonl` — варианты размещения, победители, отсеянные точки;
- `planting_explanations.md` — читаемые паспорта посадок;
- `verification_report.json` — результат независимой проверки готового плана и полного DXF.

Первые четыре файла после оптимизации планировщика побайтно совпали с исходной реализацией. JSON независимой проверки также совпал. Контрольный план содержит 3 дерева, 1 850 кустарников и 135 участков травянистого покрытия.

На объекте 10001636 те же четыре файла также совпали побайтно: 84 дерева, 4 370 кустарников и 199 участков травянистого покрытия. Сравнение включает объяснения, порядок точек и причины отклонения кандидатов.

Диагностические буферы сравниваются геометрически: площадь симметрической разности — с допуском верификатора `0.0001` квадратной единицы DXF, смещение границ — с допуском `0.0001` единицы DXF. На этом чертеже единица DXF равна метру. Эти сравнения относятся к визуализации ограничений; посадки и их объяснения проверяются отдельно на точное совпадение.

Максимальная измеренная разность площадей диагностических слоёв — `0.000001806 м²`, смещение границы — менее `0.000000195 м`. Контуры зданий, дорог и тротуаров рассчитываются прежним способом.

Регрессионные тесты проверяют неодинаковые размеры растений и масштабы, совпадающие точки, пороговые расстояния, равенство расстояний до нескольких соседей, появление новых точек между перестроениями индекса, отверстия полигонов и отсутствие переноса посадок между вариантами схемы. Фильтрация разделов DXF сравнивается с прежним чтением всех тегов на чертеже с блоками, 3D-полилиниями, пространством листа и выключенными слоями результата.

## Запуск

```powershell
.\scripts\run_pipeline.ps1 `
  -InputDxf ".\Пилотный проект 20 улиц\input_10001759_bound.dxf" `
  -OutputDirectory ".\output\demo_optimized" `
  -PipelineMode full
```

Сценарий создаёт полный DXF, диагностический чертёж, PDF с объяснениями, атлас и отчёт проверки. Для сравнения времени нужен новый каталог и режим `full`: повторный запуск `auto` может использовать кэш.

Время стадий сохраняется в `pipeline_stage_timings.md` и `pipeline_stage_timings.json` внутри каталога результата. Эти замеры включают запись файлов; профили cProfile применялись только для поиска дорогих функций и не используются как время обычного запуска.

## Память при экспорте DXF

Повторная проверка 27.09.2026 выявила `MemoryError` при чтении исходника 3-й Парковой размером 347,5 МБ. Около 300 МиБ в нём занимает секция блоков. Обычный загрузчик ezdxf сначала накапливал все промежуточные теги, одновременно с геометрией диагностики. На диске C: оставалось около 127 МБ свободного места.

Диагностика теперь создаётся из извлечённых объектов в отдельном DXF. Размер файла уменьшился с 382,7 до 38,9 МБ; все 86 587 диагностических объектов совпали с предыдущим экспортом после исключения служебных идентификаторов DXF. Контрольный экспорт диагностики занял 57,94 с.

Для полного экспорта большие ASCII DXF читаются через временное хранилище тегов секций `BLOCKS` и `ENTITIES`. Оно создаётся в выходном каталоге. Связывание объектов, аудит и сериализацию выполняет ezdxf. Готовая модель чертежа остаётся в памяти. На том же исходнике экспорт завершился за 154,62 с: пик рабочего набора процесса составил 1571 МиБ, пик выделенной памяти — 2302 МиБ. Это отдельный замер при ограниченной доступной памяти, а не повтор всего сравнительного прогона из таблицы выше.

В полном результате секции `CLASSES`, `TABLES`, `BLOCKS` и `ENTITIES` побайтно совпали с предыдущим успешным экспортом. Проверка правил и сохранности исходных объектов завершилась со статусом `passed`. SHA-256 исходного файла не изменился. Результат публикуется только после полной записи временного DXF; неудачная запись сохраняет предыдущую версию файла.
