# Первый прогон

Этот сценарий создаёт полный DXF на контрольной подоснове 3-й Парковой. Запускайте команды из корня репозитория. Для расчёта нужны Python 3.10–3.12, Go и Docker с Compose; nanoCAD нужен только для просмотра результата. `init.ps1` / `init.sh` готовят окружение и скачивают контрольный DXF из Google Drive. Скачанный файл проверяется по размеру и SHA-256, уже проверенный файл не загружается повторно.

## Windows

```powershell
& .\init.ps1
docker compose up -d --wait postgis
.\.venv\Scripts\python.exe .\scripts\seed.py
.\scripts\run_pipeline.ps1 `
  -InputDxf '.\Пилотный проект 20 улиц\input_10001759_bound.dxf' `
  -OutputDirectory '.\output\quickstart_10001759' `
  -PipelineMode full
```

Инициализация `seed.py` нужна при первом развёртывании базы и после изменения каталога растений или правил. Для повторного расчёта без таких изменений достаточно последней команды. Используйте новый выходной каталог, чтобы не смешать артефакты разных прогонов.

### Демо через интерактивное меню

В `config/openai.env` укажите ключ OpenRouter:

```dotenv
OPENROUTER_API_KEY=ваш_ключ
```

Файл исключён из Git. Для визуализаций нужен установленный Blender; его можно указать через переменную `BLENDER_EXE`, если он не обнаруживается автоматически.

```powershell
.\scripts\run_pipeline_interactive.ps1
```

По умолчанию выбраны 3-я Парковая (`input_10001759_bound.dxf`), полный расчёт, плотная смешанная посадка и фотореализм. Нажмите Enter на пункте «Построить план» или клавишу 6. При отсутствии ключа меню сообщит об этом до расчёта. Пункт 5 позволяет выбрать другой файл ключа или выключить изображения.

Результат сохраняется в `output/latest`. Если выходной DXF открыт и заблокирован, скрипт выберет отдельную папку и покажет её путь. После расчёта Blender готовит один участок с двумя одинаковыми для состояний «до» и «после» ракурсами. Затем OpenRouter создаёт до четырёх изображений в `blender_gallery/place_01/photorealistic`. Для запросов сохранён порог расходов `0.10 USD`: он останавливает последующие запросы по учтённой стоимости; фактическая цена уже отправленного запроса становится известна после ответа. Время рендеринга и генерации добавляется ко времени расчёта посадок.

## Проверка результата

В плотной смешанной посадке липа и дерен занимают два яруса: кустарник может находиться под кроной дерева. В `config/planting.json` это задают `understoryTrunkClearanceM` у дерева и `allowUnderTreeCanopy` у кустарника. Свободная область вокруг ствола имеет радиус 1 м; вся крона кустарника должна оставаться снаружи. Дополнительно действует `avoidOtherPlantingsM`: при текущих профилях между центрами дерева и кустарника требуется не менее 2 м. Это настройки композиции; отступы от инженерных сетей, люков, зданий и покрытий проверяются отдельно.

При выборе другого вида разрешение на пересечение крон автоматически не переносится. Без обоих разрешений расстояние между центрами учитывает сумму радиусов крон. Между деревьями и между кустарниками сохраняются прежние проверки шага. Параметры смешанной посадки записываются в каждую точку плана, а итоговая верификация повторно проверяет расстояния по координатам. Предпросмотр Blender использует расчётный радиус кроны дерева.

У профиля дерена также задано `existingTreeClearanceM: 1.5`: расстояние от центра нового куста до центра символа ствола существующего дерева. Оно складывается из проектного радиуса куста 0,75 м и 0,75 м свободного места от центра ствола до края куста. Кустарники могут расти под кроной существующего дерева, если проходят проверки территории и сетей. Настройка профиля имеет приоритет над общим параметром с тем же именем. При смене вида это значение автоматически не переносится. Старые профили без явного значения сохраняют прежний расчёт: условный радиус существующей кроны плюс радиус новой посадки.

Для кустарников `footprintBoundary: "physical_area"` разделяет две проверки. Центр проходит рассчитанные отступы от сетей, зданий, дороги и тротуара; полный радиус кроны помещается в физической области озеленения. Из этой области исключены покрытия, здания, люки и тепловые камеры. Радиус кустарника больше не прибавляется ко всем отступам от коммуникаций. Для профилей с `footprintBoundary: "allow_zone"` сохраняется размещение всей кроны внутри зоны отступов. Границы выбранного пользователем участка и существующие древесные массивы также ограничивают размещение.

В объяснениях каждой точки отдельно указаны проверки центра, кроны и интервала до существующих деревьев. `verify_outputs.py` повторно измеряет эти интервалы по исходной геометрии: путь берётся из отчёта расчёта, либо задаётся через `--normalized-objects`. При отсутствии источника растительности проверка нового плана завершается ошибкой. Значение 1,5 м и режим размещения кроны — проектные настройки; ссылки на применённые правила отступа сохраняются отдельно. Автоматические кустарники выстраиваются по общей оси клумбы: препятствия прерывают ряд, но не меняют его направление и шаг на соседнем фрагменте.

1. Откройте `output/quickstart_10001759/verification_report.json`. Итоговый статус должен быть `passed`; просмотрите `failures`, `planting_plan_checks`, `road_quality` и `dxf_checks`.
2. Откройте `result_with_planting_plan.dxf` в CAD. Слои результата `SYLVITECT_*` добавлены к исходному чертежу. Статический аудит DXF не заменяет эту проверку открытия.
3. Сопоставьте ID посадки в DXF с `planting_explanations.md` или `sylvitect_planting_report.pdf`. Для анализа отклонённых кандидатов используйте `planting_decisions.geojsonl`.

Windows-пайплайн также создаёт `planting_diagnostics.dxf` — самостоятельный чертёж с дорогами, зданиями, коммуникациями, посадками и слоями исключений `DEBUG_*`. Он сохраняет координаты и единицы исходника. Полная подоснова находится в `result_with_planting_plan.dxf`; диагностика использует уже извлечённые объекты и не загружает повторно все блоки исходного DXF в память. Легенда слоёв: `planting_diagnostics_legend.md`.

Существующие деревья показаны пурпурными кольцами с крестом на `DEBUG_EXISTING_TREES` поверх заливок. Принятые деревья показаны зелёными кругами на `DEBUG_PLANT_TREE`, точки кустарников — жёлтыми на `DEBUG_PLANT_SHRUB_POINTS`. Красные точки на `DEBUG_REJECTED_*` обозначают отклонённых кандидатов. Для кустарников можно включить `DEBUG_PLANT_SHRUB_IDS` с идентификаторами и `DEBUG_PLANT_SHRUB_REASONS` с проверками и ссылками на нормы; оба слоя с подписями изначально выключены. Маркеры точек отделены от площадных посадок `DEBUG_PLANT_SHRUB`, поэтому их можно скрывать независимо.

При полном экспорте ASCII DXF размером от 64 МиБ промежуточные теги блоков и объектов временно сохраняются на диске рядом с результатом. После чтения временный файл удаляется. Запись DXF выполняется через временный файл с последующей заменой готового результата: при ошибке существующий результат остаётся целым.

При ошибке сначала проверьте `pipeline_stage_timings.json` и `pipeline_run_parameters.json`: они показывают неудачную стадию, входной файл и фактический режим. Дальнейшая диагностика описана в [руководстве по эксплуатации](development.md). Режимы `fast` и `lean` пишут только облегчённый `planting_overlay.dxf`; они не заменяют полный прогон при проверке сохранения исходника.

Предложения убрать существующее дерево или одиночный куст ради композиции выводятся в `planting_plan_report.json` → `composition_advisories` и отдельными красными слоями `SYLVITECT_REMOVE_TREE_REVIEW` / `SYLVITECT_REMOVE_SHRUB_REVIEW` в результирующем DXF. Это предложения для проектной проверки; исходные растения остаются в чертеже. Если предложений нет, эти слои не создаются.

## Linux и МосТех.ОС

Для обычного Linux-хоста установите Python 3.10–3.12, Go и Docker Compose одной командой (автоматическая установка системных пакетов поддерживается на Debian/Ubuntu):

```bash
bash init.sh
bash scripts/run_pipeline_interactive.sh
```

Меню предлагает контрольный DXF 3-й Парковой, режим `full` и результат в `output/latest`. Режим `auto` делает полный первый прогон, затем использует кэш подготовки и выдаёт облегчённый оверлей. Фотореализм включается автоматически, если найдены ключ в `config/openai.env` или переменной окружения и Blender; его можно выключить в меню. Blender для этой функции устанавливается отдельно через `bash scripts/install.sh --with-blender`. Если один из них отсутствует, расчёт DXF всё равно выполняется, а этап фотографий пропускается.

Для запуска без меню:

```bash
bash scripts/run_pipeline.sh \
  'Пилотный проект 20 улиц/input_10001759_bound.dxf' \
  output/latest --mode full --preset dense_mixed
```

Команда `bash scripts/run_pipeline_interactive.sh --dry-run` проверяет входные пути и параметры без запуска расчёта и без расхода средств на изображения. Установка создаёт отдельное Linux-окружение `.venv-linux`, поэтому существующее Windows-окружение `.venv` не затрагивается. Для запуска только в контейнерах используйте [инструкцию Docker Compose](for_organizers.md#развёртывание-и-воспроизведение); в контейнере также выполняется полный актуальный набор стадий, включая диагностику и аудит существующих деревьев.
