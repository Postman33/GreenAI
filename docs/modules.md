# Справочник модулей

Здесь указана ответственность существующих пакетов и реальные точки вызова. Путь относительно корня репозитория. Общая последовательность вызовов приведена в [архитектуре](architecture.md), форматы файлов — в [контрактах данных](data_contracts.md).

## Оркестрация и системные зависимости

| Путь | Назначение | Важная граница |
|---|---|---|
| `scripts/run_pipeline.ps1` | Основной Windows-оркестратор: выбирает режим, вызывает стадии, останавливает выполнение при ненулевом коде, пишет профиль времени | Сам не реализует геометрические алгоритмы |
| `scripts/run_pipeline_interactive.ps1` | Консольное меню для выбора DXF, схемы и параметров; вызывает основной скрипт | UI оболочка, не отдельный пайплайн |
| `scripts/run_pipeline.sh` | Linux/Docker сценарий с прямыми вызовами стадий | Не идентичен PowerShell по режимам и кэшу; полный прогон после рефакторинга не подтверждён |
| `scripts/pipeline_cache.py` | Проверяет подписи входов, кода, модели и промежуточных файлов, пишет manifest | Кэширует подготовку, не сам план посадок |
| `scripts/detect_dxf_units.py` | Определяет масштаб DXF и код `$INSUNITS` | Не угадывает масштаб безразмерного чертежа |
| `scripts/seed.py`, `init.sql` | Инициализация PostGIS и идемпотентная загрузка каталога, нормативных документов и правил | Выполняется отдельно от обычного расчёта |
| `docker-compose.yml`, `Dockerfile` | PostGIS и контейнерный вариант запуска | На Windows обычный расчёт использует локальную `.venv` и контейнер только для БД |

`src/pipeline/stages.py` определяет `StageStatus`, `PipelineStage`, `StageResult`, а `artifacts.py` — тип `PipelineArtifacts` с каноническими именами части файлов. Сейчас эти классы не управляют стадиями `run_pipeline.ps1`; при изменении имени артефакта необходимо проверить и скрипт, и эти контракты, и тесты.

## CAD и геометрия

| Путь | Отвечает за | Вход / выход |
|---|---|---|
| `parser/dxf_extract_go` | Быстро читает DXF, рекурсивно обходит разрешённые блоки, сопоставляет слои с типами | DXF + YAML → `extracted_objects.jsonl` либо `surface_candidates_raw.jsonl` |
| `src/cad_io/loader.py` | Python-вариант семантического извлечения и вспомогательный доступ к CAD-записям | DXF → JSONL; не штатная стадия PowerShell-пайплайна |
| `src/geometry/normalizer.py` | Преобразует дуги, линии, символы деревьев, люки и контуры зданий в Shapely/GeoJSON | Сырые CAD-записи → `normalized_objects.geojsonl`, отчёт |
| `src/geometry/constraint_builder.py` | Классифицирует покрытия, восстанавливает дорогу, вычитает здания, тротуары, люки и камеры; допускает проверенные правки дороги | Нормализованные объекты + площадные кандидаты + сети → физическая маска и отчёт |
| `src/geometry/sidewalk_geometry.py` | Выбор пригодной геометрии тротуара для проверок | Используется правилами и планировщиком |
| `src/geometry/parts.py` | Извлечение полигональных частей из сложной геометрии | Чистая функция без CAD/БД |
| `src/core/heat_chamber_detector.py` | Ищет квадратные камеры теплосети, включая разорванные контуры | Вызывается из построения ограничений |
| `src/cad_io/surface_inspector.py` | Независимая диагностика HATCH/полилиний и их предполагаемого класса | DXF/PNG/JSON только для просмотра |
| `src/cad_io/dxf_exporter.py` | Записывает посадки, зоны и дорогу в полный DXF или оверлей; прикрепляет метаданные | План + исходный DXF → итоговый DXF |
| `src/cad_io/debug_export.py` | Вспомогательный экспорт геометрии для анализа | Не финальный проектный DXF |
| `src/cad_io/georeference.py` | Преобразования локальных координат по заданной привязке | Не включён автоматически в штатный пайплайн |

Семантический YAML `src/core/config.yaml` является **словарём типов и источников**, а `src/core/surface_inspector_config.yaml` намеренно извлекает широкий набор HATCH/замкнутых полилиний для последующей классификации. Не следует заменять семантический профиль поверхностным: это увеличит ложные объекты. Правки отдельных дорог лежат в `src/core/road_corrections/<имя_входного_DXF>.geojson` и автоматически подключаются PowerShell-скриптом при совпадении имени.

## Инженерные сети и модели

| Путь | Ответственность | Ограничение |
|---|---|---|
| `src/detection/utilities/detector.py` | Признаки CAD-примитивов, обучение, пороги и ONNX-инференс | В штатном запуске используется команда `predict` с bundle `models/utility_detector/latest` |
| `src/detection/utilities/onnx_model.py` | Экспорт и загрузка пары `*.onnx` + `metadata.json` | Формат модели — ONNX, не Joblib |
| `src/detection/cleaning/clean_utilities.py` | Эвристическая очистка, когда bundle модели отсутствует | Резервная ветка, качество надо смотреть отдельно |
| `src/detection/network_reconstructor.py` | Геометрические продолжения и тройники в уже принятых линиях; раздельные accepted/review соединения | Не делает классификацию из сырых CAD-примитивов |
| `src/detection/overhead_power_reconstructor.py` | Анализ стрелок и подписей ВЛ, создание гипотез и review-геометрии | Без подтверждения напряжения гипотеза не становится нормативной зоной |
| `src/core/network_reconstructor_config.yaml` | Допуски соединения в метрах и углах, параметры по типам сетей | Для силового кабеля и ВЛ автоматическое соединение общего реконструктора отключено |
| `ml/train.py`, `ml/validate.py` | Загрузка размеченных DXF, обучение и независимая проверка по типам сети | Цвет ACI 3 — метка обучающего примитива, не признак при инференсе |

Принятые выходы моделей хранятся в `cleaned_utilities.geojsonl`. Файлы `review_utility_graphics.geojsonl` и `rejected_utility_graphics.geojsonl` позволяют оценить ошибки модели, но не должны автоматически превращаться в подтверждённую ось сети. Конфигурация для сети и действующее правило — разные решения: например, силовой кабель не соединяется по разрывам, но для его очищенной геометрии действуют отступы. Комментарий рядом с `power_cable` в `network_reconstructor_config.yaml` относится к прежней версии правил; актуальный список — `PLACEMENT_RULES` в `scripts/seed.py` и фактические строки `plant_allow_zones_report.json` после обновления БД.

## Правила и проектирование посадок

| Путь | Ответственность | Основной контракт |
|---|---|---|
| `src/rules/plant_allow_zone.py` | Читает правила и растения из PostGIS; формирует зону каждого класса и отчёт применённых/неприменённых правил | `constraint_map.geojsonl` + нормализованные объекты + очищенные сети → `plant_allow_zones.geojsonl` |
| `src/rules/plant_allow_zone_debug.py` | Строит отдельные слои причин запрета, красные диагностические точки и легенду | `planting_diagnostics.dxf`, `planting_diagnostics_legend.md` |
| `src/rules/placement_checks.py` | Совместимый публичный импорт проверок, реализованных в `placement_generator.py` | Здесь нет собственной реализации правил |
| `src/domain/models.py` | Не зависящие от CAD типы `PlantingProfile` и `PlantingSelection` | Данные запроса и профиля |
| `src/planting/placement_generator.py` | Сетка и линейное размещение, упаковка кандидатов, геометрические проверки | Вызывается `service.py`; также имеет собственный CLI |
| `src/planting/design.py` | Геометрия аллеи, изгороди, свободной группы и цветника | Проектные схемы, не нормативные отступы |
| `src/planting/service.py` | Проверяет запрос, выбирает вид, создаёт точки/площади, журналы решений и объяснения | `planting_plan.geojsonl`, `planting_decisions.geojsonl`, `planting_layout_trace.jsonl` |
| `src/planting/api.py` | Стабильный программный вход к `plan`, профилям и зонам | Фасад над существующей реализацией |
| `config/planting.json` | Профили деревьев/кустарников/трав, шаг, габарит, лимиты и режим рядов | Значения могут быть проектными допущениями, а не нормативом |

Правила хранения разделены: `init.sql` задаёт схему, `scripts/seed.py` — данные, `plant_allow_zone.py` — вычисление зон, `service.py` — отбор конкретной посадки. Каталог содержит морозостойкость, исключение инвазивных растений, рекомендуемый шаг и радиус зрелой кроны; если источник размера не подтверждён, расчёт опирается на явно подписанный проектный профиль. Для выбранного пользователем вида применяются те же геометрические ограничения.

`src/cad_io/readers.py`, `writers.py`, `utils.py`, `src/cad_io/__init__.py`, `src/planting/__init__.py` и `src/rules/__init__.py` являются фасадами/совместимыми импортами после рефакторинга. Не ищите в них отдельный алгоритм: переходите к модулям реализации, на которые они ссылаются. Новым интеграциям полезно использовать публичные входы этих пакетов, но штатный CLI пока вызывает модули реализации напрямую.

## Отчёты, проверка и визуализация

| Путь | Назначение |
|---|---|
| `scripts/verify_outputs.py` | Независимый контроль зон, отступов, габаритов, взаимного шага, статусов и ссылок; в `full` — сохранности исходного DXF |
| `scripts/dxf_manifest.py` | Стабильное описание сущностей DXF для сравнения исходника с результатом |
| `scripts/generate_pdf_report.py` | Человекочитаемые причины отказа, сводка и паспорт каждого принятого объекта со ссылкой на источник |
| `scripts/generate_planting_atlas.py` | Иллюстрированный план и ведомость площадей по фрагментам |
| `src/visualization/prepare_scene.py`, `blender_render.py` | Подготовка сцены, масок и 3D-рендеров с фиксированными камерами «до/после» |
| `src/visualization/openrouter_images.py`, `plant_prompt.py` | Необязательная генерация более реалистичного вида по маске и перечню выбранных видов |
| `scripts/render_visualization_gallery.py`, `render_photorealistic_gallery.py` | Отдельный запуск визуализации после планирования |

Визуализация не подменяет DXF и численную проверку: у генеративного изображения нельзя измерять нормативный отступ. Ключ OpenRouter нужен только для необязательной AI-ветки; обычный план, PDF и DXF строятся без него.

## Точки изменения

| Задача | Основное место | Минимальная проверка |
|---|---|---|
| Слой на новой улице не распознан | `src/core/config.yaml` или профиль поверхностей | `tests/test_loader.py`, `tests/test_normalizer.py`, фрагмент DXF |
| Неверна реконструкция дороги | `src/geometry/constraint_builder.py`, при локальной правке `road_corrections` | `tests/test_road_reconstruction.py`, `tests/test_constraint_builder.py` |
| Ложная сеть или потерянная труба | разметка `ml/train`, `detector.py`, bundle модели | `tests/test_utility_detector.py`, независимый `ml/validate.py` |
| Ошибочно соединяется сеть | `network_reconstructor.py`, YAML допуска | `tests/test_network_reconstructor.py` |
| Неверный нормативный отступ | `scripts/seed.py`, затем БД и `plant_allow_zone.py` | `tests/test_plant_allow_zone.py`, полный прогон |
| Мало/криво расположены посадки | `config/planting.json`, `placement_generator.py`, `design.py`, `service.py` | `tests/test_placement_generator.py`, `tests/test_planting_service.py`, `tests/test_planting_design.py` |
| Неверный слой или битый DXF | `src/cad_io/dxf_exporter.py` | `tests/test_exporters.py`, `verification_report.json`, просмотр в CAD |

Полный алгоритм и границы ответственности описаны в [архитектуре](architecture.md); последовательность локального запуска и отладки — в [руководстве разработчика](development.md).
