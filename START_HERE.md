# Запуск Sylvitect-core

Sylvitect-core превращает топографический DXF в план посадок: новый DXF, PDF-отчёт с объяснениями и диагностические слои.

Распакуйте весь архив. Откройте терминал в папке `Sylvitect-core`, рядом с этим файлом. Команды ниже запускают полный расчёт демонстрационного чертежа 3-й Парковой.

## Windows

1. Откройте PowerShell в папке проекта.
2. Подготовьте зависимости и скачайте демо-чертёж:

```powershell
.\init.ps1
```

3. Запустите Docker Desktop и дождитесь готовности. Если установщик попросил перезагрузку или новое окно терминала, выполните это перед продолжением.
4. Запустите расчёт:

```powershell
.\run.ps1
```

Если Windows блокирует скрипты, используйте настройку только для текущего окна PowerShell и повторите команду:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

## Linux

```bash
bash init.sh
bash run.sh
```

Автоматическая установка системных пакетов рассчитана на Ubuntu/Debian. На других дистрибутивах, включая конкретную сборку МосТех.ОС, подготовьте зависимости самостоятельно и используйте `bash init.sh --no-system-install`. Docker должен быть запущен и доступен текущему пользователю. Контейнерный вариант описан в [README](README.md#быстрый-запуск).

## Что устанавливается

- Python 3.10–3.12, зависимости проекта, Go согласно `go.mod`, Docker с Compose.
- Окружение `.venv` на Windows или `.venv-linux` на Linux.
- Демонстрационный DXF размером около 348 МБ; загрузчик проверяет размер и SHA-256.

Для первого запуска нужен интернет и свободное место для Docker, окружения и результатов. ONNX-модели уже находятся в `models/utility_detector/latest`; обучение перед запуском не требуется. Каталог растений и правила автоматически загружаются в PostGIS при полном расчёте.

Blender и API-ключ для расчёта посадок **не нужны**. Команды `run.ps1` / `run.sh` не запускают платную генерацию изображений.

## Где результат

После завершения откройте папку `output/latest`, которую создаст расчёт:

| Файл | Назначение |
|---|---|
| `result_with_planting_plan.dxf` | Исходная подоснова и отдельные слои посадок `SYLVITECT_*` |
| `planting_plan_atlas.pdf` | Наглядные фрагменты плана и ведомость посадок |
| `sylvitect_planting_report.pdf` | Принятые и отклонённые решения, расстояния, нормативные ссылки |
| `planting_diagnostics.dxf` | Инженерные сети, ограничения и диагностические точки |
| `verification_report.json` | Результаты независимой проверки; ожидаемый статус `passed` |

На контрольной машине полный расчёт демо занимал около восьми минут; время на другой машине может отличаться. DXF открывается в nanoCAD или совместимом CAD-просмотрщике. Исходный файл не перезаписывается. Для повторного запуска закройте выходной DXF в CAD либо задайте другую папку результата.

## Свой чертёж и настройки

Windows:

```powershell
.\run.ps1 -InputDxf 'C:\drawings\street.dxf' -OutputDirectory '.\output\my_street'
```

Linux:

```bash
bash run.sh /path/to/street.dxf output/my_street --mode full --preset dense_mixed
```

Интерактивное меню: `scripts/run_pipeline_interactive.ps1` на Windows или `bash scripts/run_pipeline_interactive.sh` на Linux. В меню доступны выбор DXF, режима, пресета и визуализации. Перед запуском проверьте пункт 5: фотографии требуют отдельного Blender и API-ключа и могут быть платными.

Слои нового чертежа должны распознаваться картой `src/core/config.yaml`. При отсутствии обязательных объектов расчёт остановится; подробности — [эксплуатация и диагностика](docs/development.md).

## Если не запускается

- **Не найден DXF или окружение:** повторите `init.ps1` / `init.sh`; первая установка должна завершиться без ошибки.
- **Не подключается Docker:** запустите Docker Desktop/Engine; проверьте `docker info`.
- **Порт 5432 занят:** выполните `docker ps` и определите, какая БД его использует. Проект запускает PostGIS на этом порту; существующие контейнеры и данные автоматически не удаляются.
- **Нужно проверить только параметры:** Windows — `.\run.ps1 -ValidateOnly`; Linux — `bash scripts/run_pipeline_interactive.sh --dry-run`.
- **Ошибка на стадии расчёта:** сохраните текст ошибки и посмотрите `output/latest/pipeline_stage_timings.json`.

Архитектура, алгоритмы, форматы данных и ограничения: [документация](docs/README.md). Полный прогон проверен на Windows и в Linux-контейнере Debian: [результаты проверки](docs/platform_validation.md). Для конкретной сборки МосТех.ОС нужна отдельная проверка.
