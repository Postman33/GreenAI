# Запуск пайплайна от DXF до результата

## Требования

- Python 3.10 или новее;
- Go;
- Docker Desktop с поддержкой `docker compose`.

Команды ниже выполняются в PowerShell из корня проекта.

## Первый запуск

```powershell
Set-Location "F:\Пилотный проект 20 улиц"

py -3.10 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install --upgrade pip
& .\.venv\Scripts\python.exe -m pip install -r .\requirements.txt

go build -buildvcs=false -o .\dxf_extract_go.exe .\parser\dxf_extract_go

docker compose up -d --wait
& .\.venv\Scripts\python.exe .\scripts\seed.py

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_pipeline.ps1 `
    -InputDxf ".\Пилотный проект 20 улиц\input_10001759_bound.dxf" `
    -OutputDirectory ".\output" `
    -DxfUnitsPerMeter 1
```

Команды `docker compose` и `seed.py` перед запуском — отдельная однократная подготовка пустой БД. Сам `run_pipeline.ps1` базу не изменяет и при обычной генерации повторно справочники не загружает.

## Повторный запуск

Если окружение, Go-экстрактор и база уже созданы:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_pipeline.ps1 `
    -InputDxf ".\Пилотный проект 20 улиц\input_10001759_bound.dxf" `
    -OutputDirectory ".\output"
```

Если PostGIS уже работает и его не нужно запускать повторно:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_pipeline.ps1 `
    -InputDxf ".\Пилотный проект 20 улиц\input_10001759_bound.dxf" `
    -OutputDirectory ".\output" `
    -SkipDatabaseStart
```

## Что выполняет скрипт

1. Поднимает PostGIS из `docker-compose.yml`, если не указан `-SkipDatabaseStart`.
2. Извлекает семантические объекты из DXF по `src/core/config.yaml`.
3. Вторым проходом извлекает площадные примитивы по `src/core/surface_inspector_config.yaml`.
4. Нормализует семантические объекты в локальную GeoJSONL-геометрию.
5. Строит диагностические материалы по покрытиям.
6. Формирует базовую область и восстанавливает проезжую часть.
7. Читает существующие правила PostGIS и рассчитывает зоны деревьев и кустарников.
8. Проверяет, что зоны не выходят за базовую область и не пересекают дорогу/твёрдые покрытия.
9. Копирует исходный DXF и добавляет отдельные слои результата.

`run_pipeline.ps1` не выполняет `INSERT`, `UPDATE`, миграции или загрузку справочников в БД.

## Основные результаты

После успешного запуска в каталоге `output` появятся:

| Файл | Назначение |
|---|---|
| `result_with_plant_zones.dxf` | исходный чертёж с отдельными слоями рассчитанных зон |
| `plant_allow_zones_debug.png` | быстрая растровая проверка зон и дороги |
| `plant_allow_zones_debug.dxf` | компактный отладочный DXF без всей подосновы |
| `plant_allow_zones.geojsonl` | геометрия допустимых зон деревьев и кустарников |
| `plant_allow_zones_report.json` | применённые и нерешённые нормативные правила |
| `constraint_map.geojsonl` | базовая область, покрытия и восстановленная дорога |
| `constraint_report.json` | площади и диагностика общих ограничений |
| `verification_report.json` | автоматическая проверка пространственных инвариантов |
| `surface_candidates.png` | диагностика найденных площадных слоёв |

В nanoCAD нужно открыть `output\result_with_plant_zones.dxf` и включить слои:

- `GREEN_AI_RECONSTRUCTED_ROAD`;
- `GREEN_AI_ZONE_TREE`;
- `GREEN_AI_ZONE_SHRUB`.

Сейчас эти слои показывают допустимые **области**, а не конкретные точки отдельных посадок. Генератор посадочных точек является следующим модулем.
