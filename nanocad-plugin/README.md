# GreenAI — экспериментальный плагин nanoCAD

## Встроенный редактор

После загрузки `GreenAI.NanoCad.dll` группа **GreenAI** появляется в нативном
контекстном меню nanoCAD: и на пустом месте, и при выбранном объекте. Для расчёта
посадки нужно передать замкнутую `POLYLINE`, `LINE` или открытую `POLYLINE`.
Основной сценарий выполняется мышью:

- выбрать на чертеже замкнутый контур рабочей зоны;
- выбрать дерево или кустарник;
- выбрать схему: сетка, вдоль границы либо ручная установка;
- настроить шаг и максимальное количество;
- построить голубой предпросмотр и затем добавить результат в чертёж;
- включать и выключать слои деревьев, кустарников, предпросмотра и ошибок;
- автоматически перепроверять посадки после `MOVE`, копирования, удаления и
  других изменений объектов GreenAI;
- при необходимости запускать проверку всех посадок отдельной кнопкой.

При ручной установке точка проверяется сразу. Недопустимая точка не добавляется
как растение: на слое `GREEN_AI_REVIEW` появляется красный маркер, а панель
показывает расстояние, нарушенное правило и нормативную ссылку. Все действия
записываются в журнал панели.

Расширенная панель открывается через **GreenAI → Открыть расширенную панель**
в контекстном меню либо командой `GREENAI_PANEL`.

Плагин находится в отдельной папке и не меняет основной Python/Go-пайплайн.
Он читает промежуточные GeoJSONL-файлы, применяет правила расстояний на стороне
.NET, генерирует точки посадки, проверяет их и записывает результат в открытый
чертёж nanoCAD.

## Что уже работает

- чтение `constraint_map.geojsonl`, `normalized_objects.geojsonl` и
  `reconstructed_utilities.geojsonl`;
- самостоятельное вычитание дороги, твёрдых покрытий, тротуаров и колодцев
  из подтверждённой поверхности;
- вычитание нормативных буферов для каждого класса посадки;
- использование восстановленных линий газа, воды и теплосети;
- детерминированная гексагональная расстановка деревьев и кустарников;
- проверка попадания точки в разрешённую область;
- повторная проверка расстояний до каждого объекта;
- проверка шага между новыми растениями;
- отдельный статус `manual_review`, если правило нельзя применить автоматически;
- JSON-отчёт с правилами, нормами и причинами ручной проверки;
- повторный запуск без накопления старых объектов.

Минимальный шаг 5 м для деревьев и 2 м для кустарников в конфигурации — демонстрационные
параметры компоновки, а не значения, извлечённые из нормативного документа.
Обычный смешанный сценарий разрежает деревья примерно до 6 м, а плотный
смешанный использует 5 м — диаметр принятой взрослой кроны. В смешанном плане
кустарники формируют краевые массивы, газон занимает остаток, а кустарниковые
полигоны вырезаются вокруг взрослых габаритов деревьев.

В редакторе шаг задаётся между центрами растений. Для текущей липы интерфейс не
даёт опустить его ниже 5 м при расчётном радиусе взрослой кроны 2,5 м; для
спиреи — ниже 1,5 м при радиусе 0,75 м. Эти размеры являются проектными
допущениями MVP и должны уточняться по выбранному посадочному материалу перед
рабочим проектированием.

## Сборка

Для nanoCAD 26 используется .NET 6 и x64. В PowerShell из корня проекта:

```powershell
.\nanocad-plugin\build.ps1
```

Готовые файлы появятся в `nanocad-plugin\build`:

- `GreenAI.NanoCad.dll`;
- `GreenAI.Core.dll`;
- `NetTopologySuite.dll`;
- `greenai.plugin.json`.

Все файлы должны оставаться рядом. Путь к библиотекам nanoCAD можно передать:

```powershell
.\nanocad-plugin\build.ps1 -NanoCadDir "F:\NanoCAD\bin"
```

## Проверка вычислительного ядра без nanoCAD

```powershell
.\nanocad-plugin\test.ps1
```

Тест запускает именно C#-движок на файлах из `output`, генерирует точки и
проверяет каждую из них теми же правилами, которые использует плагин.

Полная проверка собранной DLL внутри установленного nanoCAD:

```powershell
.\nanocad-plugin\validate_nanocad.ps1
```

Скрипт запускает отдельный скрытый экземпляр nanoCAD, проверяет запись результата
в ModelSpace, XData и JSON-отчёт, после чего закрывает только созданный им процесс.

## Запуск в nanoCAD

Для запуска без команд и поиска DLL дважды щёлкните
`nanocad-plugin\start_greenai.cmd`. Откроется подготовленный чертёж и загрузится
проверенная сборка. Выделите линию или полилинию и щёлкните правой кнопкой мыши.

Ручной вариант:

1. Открыть `output\verification_final_20260920\result_with_planting_plan.dxf`
   либо результат своего последнего полного прогона.
2. Открыть **Управление → Приложения → Загрузить .NET-приложение**.
3. Выбрать `nanocad-plugin\build\GreenAI.NanoCad.dll`.
4. Выделить `LINE` или `POLYLINE` и открыть группу **GreenAI** через ПКМ.

Командная строка nanoCAD для обычной работы не нужна. После загрузки DLL
пресеты, параметры, применение предпросмотра и показ результата доступны через ПКМ.

Если в nanoCAD уже загружалась прежняя версия плагина, полностью закройте
nanoCAD и запустите его заново: загруженную DLL нельзя заменить в работающем
процессе.

### Самый простой сценарий

В верхней части панели нажмите большую зелёную кнопку
**СОЗДАТЬ ПЛАН ОЗЕЛЕНЕНИЯ**. Плагин сам:

1. находит подготовленные данные для открытого чертежа;
2. определяет рабочую область и запретные зоны;
3. плотно размещает деревья и кустарники и формирует травянистое покрытие;
4. приближает камеру к результату;
5. показывает количество посадок и результат проверки в панели.

Алгоритм проверяет полный радиус взрослой кроны. Круг дерева или кустарника не
может выступать за выбранный контур либо пересекать запретную зону. Для плотного
заполнения сравниваются несколько сдвигов и направлений гексагональной сетки.
Существующие деревья и древесные полосы также учитываются. Минимальное
расстояние между центром существующего дерева и центром новой посадки задаётся
явным проектным параметром `existingTreeClearanceM` (сейчас 2 м). Это
геометрическое допущение проекта, а не нормативный отступ из СП. Старый параметр
`existingTreeCanopyRadiusM` используется только как совместимый резерв для
конфигураций, в которых новое поле отсутствует.

### Редактирование выбранной зоны

1. Нажать **Выбрать замкнутый контур на чертеже** и указать полилинию.
2. Выбрать один из вариантов:
   - смешанный план;
   - только деревья;
   - только кустарники;
   - газон / травянистое покрытие.
3. Нажать **Предпросмотр**. Голубые объекты ещё не изменяют готовый план.
4. Проверить количество посадок и процент допустимой площади, показанные в
   панели, затем нажать **Добавить в чертёж**.

### Ровный ряд вдоль проектной линии

Для аллеи или линейной посадки площадная сетка не нужна:

1. Начертить обычную `LINE` или открытую/закрытую `POLYLINE` по желаемой оси ряда.
2. Нажать **Выбрать линию посадки (LINE / POLYLINE)** и указать эту ось.
3. Выбрать дерево или кустарник и задать шаг в метрах.
4. Нажать **Предпросмотр**, затем **Добавить в чертёж**.

Плагин центрирует равномерный ряд по длине линии. Точки, нарушающие допустимую
область, отступы от объектов или расстояния до существующих посадок, в ряд не входят.

Для каждой посадки доступны кнопки:

- **Информация** — показывает встроенный паспорт с координатами, видом,
  фактическими расстояниями, нормативными минимумами и ссылками на нормы;
- **Перенести** — переносит выбранное растение и сразу повторяет проверку;
- **Удалить** — удаляет выбранную посадку или весь фрагмент покрытия;
- **Проверить все посадки** — отмечает нарушения красным слоем.

Плагин добавит:

- `GREEN_AI_PLANT_TREE` — предлагаемые деревья;
- `GREEN_AI_PLANT_SHRUB` — предлагаемые кустарники;
- `GREEN_AI_HERBACEOUS` — газон и травянистые покрытия;
- `GREEN_AI_REVIEW` — точки, в которых проверка обнаружила нарушение.

Правила, требующие экспертной проверки всего слоя, записываются в JSON-отчёт и
не создают сотни одинаковых маркеров на чертеже.

Кнопка **Проверить все посадки** повторно проверяет текущие круги. После
перемещения посадки стандартными средствами nanoCAD проверка также запускается
автоматически. Нарушения будут обведены красным на `GREEN_AI_REVIEW`, а причины
появятся прямо в панели и попадут в
`output\nanocad_plugin_report.validation.json`.

Кнопка **Очистить результат** удаляет только созданные плагином сущности.
Исходные слои не изменяются.

Если файлы анализа лежат не рядом с открытым DXF, задайте переменную окружения:

```powershell
$env:GREENAI_DATA_DIR = "F:\Пилотный проект 20 улиц\output"
```

## Граница прототипа

Плагин самостоятельно выполняет правила и посадку, но использует геометрию,
которую подготовили экстрактор, нормализатор и реконструктор. CAD-разбор
миллиона примитивов и ONNX-классификация остаются вне DLL. Это позволяет
проверить интерактивный сценарий без дублирования наиболее тяжёлых модулей.

Плагин не подтверждает неоднозначные ЛЭП и не применяет сырой слой сети, если
для правила требуется очищенная или восстановленная геометрия.

## Результат end-to-end проверки

Базовая CAD-интеграция проверена 20.09.2026 на установленном `nanoCAD x64 26.0`
и .NET runtime 6.0.11. Скрытый end-to-end тест загрузил актуальную сборку
`nanocad-plugin\build\GreenAI.NanoCad.dll` поверх проверенного пакетного DXF:

- контекстный пресет применён к выбранной полилинии;
- выбранный объект сохранён как рабочая зона;
- предпросмотр из контекстного меню успешно сгенерирован;
- точечные и площадные результаты получают уникальные ID и метаданные паспорта;
- ссылка посадки на пользовательский контур сохраняется в XData: тестовый
  перенос за контур корректно отклонён;
- JSON-отчёт создан.

Контекстный пресет **Деревья — шаг 5 м** передаёт обработчику параметры
`plantType=tree`, `spacingM=5`. Core smoke-тест на текущем наборе строит 370
деревьев в обычном сценарии и 394 в плотном/максимальном сценарии.

Для всей территории доступны сценарии: сбалансированный, плотный смешанный,
максимум деревьев, максимум количества растений и только травянистое покрытие. Их количество
зависит от текущей геометрии, каталога и набора подтверждённых ограничений.

Команда `GREENAI_INSPECT` для красной диагностической точки показывает все
конкретные причины отказа: фактическое и требуемое расстояние, недостающий
отступ, рекомендацию по исправлению и источник правила. Технический код
проверки выводится последней строкой причины.

Отчёты проверки находятся в:

- `output\verification_final_20260920\nanocad_smoke_20260920_204921.json`;
- `output\verification_final_20260920\nanocad_probe_20260920_204921.json`.

Статус `manual_review` не означает геометрическую ошибку. Он показывает, что
для объекта остаются правила, которые исходный набор не позволяет подтвердить
автоматически: например, охранная зона ЛЭП без надёжного класса напряжения.
